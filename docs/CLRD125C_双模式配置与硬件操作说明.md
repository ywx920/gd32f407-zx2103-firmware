# CLRD125C V1.0 双模式配置与硬件操作说明

## 1. 目的和适用范围

本文用于指导ZX2205-3板卡将原LT1258替换为CLRD125C-K V1.0，覆盖以下两种使用方式：

1. 不修改现有硬件，使用CLRD125C引脚控制模式；
2. 修改少量配置电阻，使用MCU SMBus从机模式精细配置CLRD125C。

工程路径：

`20241202/project_up_new`

控制方式在以下文件中选择：

`bsp/clrd125c_v1.h`

```c
#define CLRD125C_CONFIG_MODE CLRD125C_CONFIG_MODE_PIN
```

或者：

```c
#define CLRD125C_CONFIG_MODE CLRD125C_CONFIG_MODE_SMBUS
```

程序统一调用：

```c
clrd125cInitSelectedMode();
```

## 2. CLRD125C的三种控制方式

CLRD125C上电时根据ENSMB引脚决定控制方式。

| ENSMB状态 | 工作方式 | 配置来源 |
|---|---|---|
| 1 kΩ接GND | 引脚模式 | EQ、DEM、MODE、SEL、INPUT_EN等外部电阻 |
| 1 kΩ接VDD | SMBus从机模式 | MCU写寄存器 |
| 悬空 | SMBus主机模式 | CLRD125C从外部EEPROM加载 |

现有原理图把ENSMB通过1 kΩ拉低，因此当前实物默认是引脚模式。

## 3. 方式一：不修改硬件的引脚模式

### 3.1 软件如何选择

在`bsp/clrd125c_v1.h`中设置：

```c
#define CLRD125C_CONFIG_MODE CLRD125C_CONFIG_MODE_PIN
```

程序不会初始化GPIO I2C、不会扫描地址，也不会写CLRD125C寄存器，而是打印：

```text
[CLRD125C] PIN mode selected (no hardware change)
[CLRD125C] SMBus access skipped: ENSMB is expected LOW
[CLRD125C] route/EQ/DEM/MODE are sampled from board resistors
```

这里返回`STA_OK`表示程序已正确选择现有硬件的工作方式，不代表软件已经回读或验证了CLRD125C参数。

### 3.2 当前硬件如何配置芯片

以原理图第8页U11为例：

- ENSMB下拉：选择引脚模式；
- RESET由4.7 kΩ下拉：器件正常工作；
- SEL0、SEL1约20 kΩ下拉：选择B侧输入、A侧输出；
- INPUT_EN为低：关闭Fanout，按SEL0/SEL1选择路径；
- EQ_D[1:0]、EQ_S[1:0]：由板上1 kΩ电阻档位决定输入均衡；
- DEM_D[1:0]、DEM_S[1:0]：由板上1 kΩ电阻档位决定输出摆幅和去加重；
- MODE：由原LT1258的REXT位置及阻值决定当前逻辑档位。

预期主要路径：

```text
S_INB0 -> D_OUT0
S_INB1 -> D_OUT1
D_IN0  -> S_OUTA0
D_IN1  -> S_OUTA1
```

### 3.3 引脚模式能够达到的效果

优点：

- 不需要改板；
- 不需要MCU通信；
- 上电立即按固定电阻工作；
- 启动逻辑简单，不会出现I2C NACK导致初始化失败。

限制：

- 只能使用四级输入提供的有限档位；
- D侧/S侧通常成组设置，不能对每条路径独立精调；
- MCU无法读取实际配置；
- 无法确认配置电阻焊接错误；
- 无法精确设置当前目标的CTLE约17.7 dB、VOD约0.8 V、DEM约-5 dB；
- 参数变化需要改电阻。

### 3.4 引脚模式验证方法

1. 上电确认CLRD125C各电源符合手册要求；
2. 测量RESET为低、ENSMB为低；
3. 不要把SCL/SDA NACK作为故障依据，因为引脚模式不会响应SMBus；
4. 输入测试码型，确认四条预期路径均有输出；
5. 检查输出摆幅、上升下降时间和过冲；
6. 使用眼图或误码仪比较替换前后的眼高、眼宽和BER；
7. 在高低温和电源上下限条件下复测。

## 4. 方式二：SMBus从机模式

### 4.1 U11需要修改的硬件

以下位号对应原理图第8页U11。

#### ENSMB模式选择

- 拆除R151：当前1 kΩ到GND；
- 安装R150：1 kΩ到VCCIO；
- 禁止R150和R151同时安装。

修改后ENSMB为高，CLRD125C进入SMBus从机模式。

#### MCU到CLRD125C的总线连接

- 安装R127：0 Ω，连接MCU SCL到CLRD125C Pin50；
- 安装R128：0 Ω，连接MCU SDA到CLRD125C Pin49。

当前R127/R128标记为NC，未安装时MCU不能访问CLRD125C。

#### 外部EEPROM支路

当前：

- R129连接MCU SCL到U10 EEPROM；
- R130连接MCU SDA到U10 EEPROM。

有两种处理方法：

1. 调试推荐：拆除R129/R130，使CLRD125C独占这条总线；
2. 量产可选：保留R129/R130，让EEPROM和CLRD125C共享总线，但必须确认地址不冲突、上拉及总线电容满足要求。

#### 地址配置

SMBus模式下，原复用的DEM_D/EQ_S引脚成为AD0~AD3地址脚。当前U11相应配置电阻均为下拉时：

```text
AD[3:0] = 0000
7位地址 = 0x58
线上写地址 = 0xB0
线上读地址 = 0xB1
```

工程仍保留一次早期地址0x30的兼容探测，但CLRD125C V1.0标准地址范围是0x58~0x67。

#### 其他硬件检查

- RESET保持低为正常工作；
- 确认SCL/SDA有合适的上拉；
- MCU使用PB10作为SCL、PB11作为SDA；
- 确认VDD_SEL、VDD和VIN符合2.5 V或3.3 V供电模式要求；
- 焊接后断电测量SCL/SDA到芯片管脚的通断和对地阻值。

### 4.2 其他器件位置

U13、U15、U17采用相同原则：

1. ENSMB由下拉改为上拉；
2. 安装芯片SCL/SDA到MCU总线的0 Ω连接；
3. 根据是否保留EEPROM决定其支路0 Ω是否安装；
4. 利用AD[3:0]给四颗芯片设置不同地址。

不要让多颗CLRD125C使用相同地址连接在同一总线上。

### 4.3 软件如何选择

修改：

```c
#define CLRD125C_CONFIG_MODE CLRD125C_CONFIG_MODE_SMBUS
```

启动程序执行：

1. 等待上电500 ms；
2. 检查SCL/SDA空闲电平；
3. 扫描0x58~0x67；
4. 读取寄存器确认从机可访问；
5. 配置寄存器接管EQ、DEM、MODE、EN_HF和路由；
6. 配置四条有效通道；
7. 对每个关键寄存器执行读改写和回读校验；
8. 读取RX_DETECT和RX_LOS。

当前驱动按“一颗芯片调试”设计：扫描到第一颗应答器件后完成配置。若U11、U13、
U15、U17全部改为SMBus模式，必须为四颗芯片设置不同AD[3:0]地址，并把驱动扩展为
逐地址配置；不能只依赖当前的第一地址命中逻辑。

### 4.4 当前SMBus目标配置

| 项目 | 配置 |
|---|---|
| 路由 | B侧输入到A侧输出 |
| Fanout | 关闭 |
| 有效通道 | CH1、CH3、CH4、CH6 |
| CTLE | Code 0x09，EN_HF=1，约17.7 dB |
| 模式 | 非线性 |
| VOD | Code 010，约0.8 Vp-p |
| DEM | Code 010，约-5 dB |

该配置用于近似原LT1258的有效路径、约17.6 dB均衡、0.8 V输出和约-4.4 dB去加重。CLRD125C没有精确-4.4 dB档位，因此先选-5 dB，并建议与-3.5 dB比较。

### 4.5 SMBus模式验证方法

启动日志至少应出现：

```text
[CLRD125C] probe V1.0 7-bit=0x58 write=0xB0 ... ACK
[CLRD125C] selected: 7-bit=0x58 write=0xB0 read=0xB1
[CLRD125C] V1.0 initialization complete
```

然后检查：

1. 每个配置项均有old/new回读结果；
2. 不出现`verify failed`；
3. RX_DETECT和RX_LOS与实际输入信号一致；
4. 用逻辑分析仪确认地址、寄存器地址、数据和ACK；
5. 最终仍需用眼图和BER验证模拟效果，寄存器回读成功不等于信号质量已经最优。

## 5. 方式三：EEPROM自动加载

ENSMB悬空时，CLRD125C作为SMBus主机从外部EEPROM读取配置。

适合：

- 参数已经完全定型；
- 不希望MCU参与初始化；
- 上电需要自动加载固定配置的量产产品。

缺点：

- EEPROM内容和加载格式必须严格验证；
- 调参不如MCU方便；
- 当前板上EEPROM原先用于LT1258，其内容不能直接视为CLRD125C配置；
- 故障定位和版本管理复杂于MCU配置。

当前阶段不推荐直接采用。

## 6. 三种方式效果对比

| 项目 | 引脚模式 | MCU SMBus模式 | EEPROM模式 |
|---|---|---|---|
| 是否需要改当前硬件 | 否 | 是 | 可能需要 |
| 参数精度 | 低，固定档位 | 高，逐寄存器 | 高，取决于镜像 |
| 逐通道配置 | 受限 | 支持 | 支持 |
| 软件回读 | 不支持 | 支持 | MCU通常不能直接确认全部加载内容 |
| 现场调参 | 需要改电阻 | 改配置表即可 | 重写EEPROM |
| 启动复杂度 | 最低 | 中等 | 中等 |
| 故障诊断 | 较弱 | 最好 | 较弱 |
| 量产一致性 | 依赖电阻公差和焊接 | 可回读校验 | 依赖EEPROM内容 |

## 7. 参数如何选择

### 7.1 CTLE

先计算每条输入路径在奈奎斯特频率处的插入损耗：

```text
奈奎斯特频率 = NRZ数据速率 / 2
目标CTLE约等于输入路径在该频率处的损耗
```

初始值建议比估算损耗低1~3 dB，然后逐级增加，通过眼图和BER寻找最佳点。

### 7.2 VOD

从0.8 V开始：

- 接收端幅度不足时增加；
- 过冲、串扰、功耗或接收端过驱时降低。

### 7.3 DEM

DEM补偿的是CLRD125C输出到下一级接收端的高频损耗。短路径优先使用较小DEM，当前建议先比较-3.5 dB和-5 dB。

### 7.4 调试原则

1. 每次只改变一个参数；
2. 四条路径分别记录结果；
3. 不以“能够连接”作为最终标准；
4. 同时观察眼高、眼宽、总抖动和BER；
5. 完成多板、高低温和电源裕量测试。

## 8. 推荐方案

### 当前板卡快速验证

使用引脚模式，不改硬件：

```c
#define CLRD125C_CONFIG_MODE CLRD125C_CONFIG_MODE_PIN
```

这可以立即停止无意义的I2C扫描，并验证CLRD125C在现有电阻档位下能否建立四条高速路径。但其结果只能作为兼容性和连通性验证，不能证明已经完全复现LT1258的信号调理效果。

### 最终推荐

最推荐使用MCU SMBus从机模式。

理由：

- 能精确接近原LT1258配置；
- 每条路径可以独立调节；
- 能回读并判断初始化是否真实成功；
- 后续更换PCB、连接器、线缆或速率时只修改配置表；
- 最适合眼图和BER调试；
- 参数定型后仍可保留配置版本、校验和故障回退。

推荐实施顺序：

1. 先用当前引脚模式确认器件焊接、电源和高速路径基本正常；
2. 修改一颗U11进入SMBus模式，完成通信和参数调试；
3. 固化每条路径的最佳参数；
4. 再将其他CLRD125C按不同地址接入；
5. 完成多板、高低温、供电裕量和BER测试后量产。
