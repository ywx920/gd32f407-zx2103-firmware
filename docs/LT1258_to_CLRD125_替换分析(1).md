## 1. 项目背景

ZX2103-1A 项目当前使用 **4 片 LT1258**（U11/U13/U15/U17）作为高速信号调理芯片，由 **GD32F407 MCU** 通过 I2C 总线直接控制。
> **注**：原理图中虽然设计了 AT24C04 EEPROM，但实际调试中并未使用，所有配置均由 MCU 直接写入。

出于供应链或成本考虑，拟将 LT1258 替换为国产方案 **CLRD125C-K**（核芯互联）。本文档基于原理图网表、两份数据手册、寄存器配置表及扫描版引脚图，对替换可行性进行全面分析。

### 1.1 当前硬件架构

```
GD32F407 MCU ──I2C──► LT1258 (×4) ──高速信号──► PCIe/SATA/SAS 链路
              └── 控制信号：SEL0/SEL1/INEN/RESET
```
> **注**：AT24C04 EEPROM 在原理图中有设计，但实际未使用。

### 1.2 当前 I2C 配置参数（来自调试记录）

| 参数 | 当前配置 |
|------|----------|
| I2C 工作模式 | Slave 模式（LT1258 为 Slave） |
| I2C 上拉电阻 | 250Ω（4 颗 1KΩ 并联） |
| 电容 C152/C153 | 已恢复为原设计电容（调试期间曾临时改为 0Ω）|
| EQ 配置 | 原 Pin 模式 9.6dB，现改为 I2C 配置 |

### 2.1 I2C 地址配置详解

#### 原理图硬件配置

每片 LT1258 的 I2C 设备地址由 **AD[3:0] 引脚**（Pin 46/47/53/54）通过上下拉电阻配置：

| AD 引脚 | 原理图位号 | 引脚编号 | 配置方式 |
|---------|-----------|---------|---------|
| AD0 | R142/R143, R199/R200, R256/R257, R313/R314 | Pin 54 | 1KΩ 下拉（焊接）/ 1KΩ 上拉（NC）|
| AD1 | R144/R145, R201/R202, R258/R259, R315/R316 | Pin 53 | 1KΩ 下拉（焊接）/ 1KΩ 上拉（NC）|
| AD2 | R152/R153, R209/R210, R266/R267, R323/R324 | Pin 47 | 1KΩ 下拉（焊接）/ 1KΩ 上拉（NC）|
| AD3 | R154/R155, R211/R212, R268/R269, R325/R326 | Pin 46 | 1KΩ 下拉（焊接）/ 1KΩ 上拉（NC）|

> **说明**：每片 LT1258 的每个 AD 引脚都预留了一对 1KΩ 电阻（一个接 GND，一个接 VCCIO），通过**焊接/不焊接（NC）**来配置该位为 0 或 1。

#### 实际代码中的 I2C 地址

从 `LT1258.h` 驱动代码中，4 片芯片的实际 I2C 地址定义如下：

```c
#define LT1258_DEVICE_ADDR_1 0x18  // 对应 8 位写地址 0x30
#define LT1258_DEVICE_ADDR_2 0x1C  // 对应 8 位写地址 0x38
#define LT1258_DEVICE_ADDR_3 0x20  // 对应 8 位写地址 0x40
#define LT1258_DEVICE_ADDR_4 0x24  // 对应 8 位写地址 0x48
```

| 芯片位号 | 7 位 I2C 地址 | 8 位写地址 | 8 位读地址 | 备注 |
|---------|-------------|-----------|-----------|------|
| U11 (第 1 片) | **0x18** | 0x30 | 0x31 | 代码中使用 |
| U13 (第 2 片) | **0x1C** | 0x38 | 0x39 | 代码中使用 |
| U15 (第 3 片) | **0x20** | 0x40 | 0x41 | 代码中使用 |
| U17 (第 4 片) | **0x24** | 0x48 | 0x49 | 代码中使用 |

#### CLRD125 地址兼容性

CLRD125 在 I2C 模式下同样使用 **AD[3:0] 引脚**配置设备地址：

| 引脚 | CLRD125 (I2C 模式) | LT1258 | 兼容性 |
|------|-------------------|--------|--------|
| Pin 46 | EQ_S0 / **AD3** | AD3 | ✅ |
| Pin 47 | EQ_S1 / **AD2** | AD2 | ✅ |
| Pin 53 | DEM_D1 / **AD1** | AD1_DEMD0 | ✅ |
| Pin 54 | DEM_D0 / **AD0** | AD0_DEMD1 | ✅ |

**结论**：
1. **引脚位置完全相同**：CLRD125 的 AD0~AD3 引脚与 LT1258 位于相同的物理位置（Pin 46/47/53/54）
2. **硬件配置可直接沿用**：原设计的上下拉电阻配置无需改动
3. **代码地址可直接沿用**：CLRD125 支持相同的 I2C 地址范围，软件中定义的 4 个地址（0x18/0x1C/0x20/0x24）可直接复用

> **替换时 I2C 地址无需任何修改**，这是引脚兼容性的重要体现。

## 4. 硬件改动清单

根据 FAE 反馈：**在 I2C 模式下，Pin 21（MODE 引脚）的配置可以不用考虑。** 这意味着硬件改动量进一步降低。

### 4.1 必须修改

**无必须修改项。** 所有引脚在 I2C 模式下均可直接兼容或保持现状。

### 4.2 建议修改

| 序号 | 位置 | 当前状态 | 建议操作 | 优先级 |
|------|------|----------|----------|--------|
| 1 | Pin 21（REXT 电阻）| 12KΩ 到 GND | 可保持现状或拆除 | 低（FAE 确认 I2C 模式不影响）|
| 2 | Pin 51（去耦电容）| NC/悬空 | 建议补 0.1μF 到 GND | 低（3.3V 模式下已有其他 VDD 去耦）|

### 4.3 无需改动

- **所有高速信号引脚**：完全兼容
- **Pin 6, 12, 13**：SMBus/I2C 模式下为 NC，悬空即可
- **I2C 地址配置引脚（AD0~AD3）**：地址范围相同
- **控制引脚**：ENSMB/SEL0/SEL1/RESET/VDD_SEL 等保持原配置

## 5. 软件改动清单（主要工作量）

### 5.1 I2C 通信协议重写

| 项目 | LT1258 | CLRD125C-K |
|------|--------|------------|
| **寄存器寻址** | Bank + Offset（需先写 Bank 地址）| 扁平地址（0x80 + regnum）|
| **Bank 切换** | 写 0xFF 寄存器切换 Bank | **不需要** |
| **I2C 地址范围** | 0xB0 ~ 0xBE（偶数地址）| 0xB0 ~ 0xBE（偶数地址）|

**关键差异**：CLRD125 没有 Bank 概念，所有寄存器通过 `0x80 + 寄存器号` 直接访问。

### 5.2 初始化序列重写

CLRD125 建议的初始化流程（来自调试文档）：

```c
// 步骤 1：禁用引脚控制，使能寄存器控制
WriteReg(0x86, 0xE0);  // Reg6:  禁用引脚 EQ/VGA/DEM 控制
WriteReg(0x88, 0x0C);  // Reg8:  禁用引脚 MODE/ENHF 控制
WriteReg(0xCE, 0x07);  // Reg78: 禁用引脚 SEL/INPUT_EN 控制

// 步骤 2：按通道配置 CTLE / VOD / DEM
// 通道 0 Downlink
WriteReg(0x90, ctle_ctrl_ch0);   // Reg16
WriteReg(0x91, vod_ctrl_ch0);    // Reg17
WriteReg(0x92, dem_ctrl_ch0);    // Reg18
// ... 其他通道类似
```

### 5.3 EQ / DEM / VOD 参数映射

| 参数 | LT1258（当前） | CLRD125 对应配置 |
|------|---------------|-----------------|
| EQ | 9.6 dB（Pin 模式） | `ctle_ctrl ≈ 0x0B~0x0C`, `en_hf = 0` |
| DEM | 默认 | 从 `-9.5 dB`（默认值）开始调试 |
| VOD | 默认 | 从 `1.1 V`（默认值）开始调试 |

**注意**：CLRD125 支持 **64 级 EQ**，比 LT1258 的粗粒度 EQ 更精细，需要重新标定最优值。

### 5.4 状态/中断处理

- **LT1258 Pin 27 (INT)**：中断输出
- **CLRD125 Pin 27 (ALL_DONE)**：上电校准完成指示

如果当前软件使用了 LT1258 的中断功能，需要评估是否改为轮询 ALL_DONE 状态。

## 7. 调试建议

### 7.1 调试流程

1. **硬件检查**：确认 4 片芯片焊接正常，I2C 总线通畅
2. **基础通信**：验证 MCU 能正确读写 CLRD125 寄存器（如读取芯片 ID）
3. **初始化验证**：按推荐序列写入初始化配置，确认无报错
4. **信号测试**：
   - 先用默认参数测试链路通断
   - 逐步调整 EQ/DEM/VOD，观察眼图改善
   - 记录最优参数组合
5. **长时间稳定性**：高温/低温/振动条件下验证

### 7.2 走线长度分析与参数预估

根据 `走线长度分析.png`，系统链路结构如下（PCB 板材：TU872-SLK）：

```
FPGA (板卡1) ──2500mil──► VPX ──2000mil──► VPX (板卡2) ──5300mil──► CLRD125 ──1800mil──► 光模块
```

| 链路段 | 走线长度 | 备注 |
|--------|----------|------|
| 板卡1：FPGA → VPX | 2500 mil (63.5 mm) | 驱动端输出 |
| 背板：VPX → VPX | 2000 mil (50.8 mm) | 背板跨接 |
| 板卡2：VPX → CLRD125 | 5300 mil (134.6 mm) | **板卡2最长走线段** |
| 板卡2：CLRD125 → 光模块 | 1800 mil (45.7 mm) | 较短 |
| **总链路（FPGA → 光模块）** | **11600 mil (294.6 mm)** | — |

**对 CLRD125 参数调试的影响**：

- **Downlink 方向（FPGA → 光模块）**：
  - CLRD125 的 **D_IN** 接收端信号已走过 `2500 + 2000 + 5300 = 9800 mil`（约 249 mm）
  - 在 5 Gbps 速率下，经过长距离传输后高频衰减明显
  - **建议**：D_IN 通道的 **EQ 适当提高**（从 `ctle_ctrl = 0x0C~0x10` 开始调试）

- **Uplink 方向（光模块 → FPGA）**：
  - 光模块输出信号经 CLRD125 的 **S_IN → S_OUT** 整形后，再经过 `5300 + 2000 + 2500 = 9800 mil` 到达 FPGA
  - CLRD125 到光模块仅 1800 mil，接收端走线短
  - **建议**：S_IN 通道的 **EQ 适中**（从 `ctle_ctrl = 0x08~0x0C` 开始调试），**S_OUT 的 DEM 适度预补偿**

- **PCB 材料 TU872-SLK**：
  - 低损耗高速板材（Dk ≈ 3.8~4.0，Df ≈ 0.008~0.01）
  - 对 5 Gbps 信号的插入损耗相对可控，但 9800 mil 仍属中长距离
  - 实际参数需以眼图测试结果为准，上述仅为初始预估

### 7.3 关键寄存器速查

| 寄存器号 | I2C 地址 | 功能 | 建议初始值 |
|----------|----------|------|-----------|
| Reg6 | 0x86 | 引脚控制禁用 | 0xE0 |
| Reg8 | 0x88 | 引脚控制禁用 | 0x0C |
| Reg16 | 0x90 | CH0 Down CTLE | 按调试确定 |
| Reg17 | 0x91 | CH0 Down VOD | 按调试确定 |

## 8. 注意事项

### 8.1 硬件方面

1. **Pin 21 (MODE)**：FAE 确认 I2C 模式下无需特殊配置，但建议保留原理图标注，以便后续维护人员了解。
2. **Pin 51 (VDD)**：虽然 3.3V 模式下其他 VDD 引脚的去耦足够，但如果空间允许，建议补一颗 0.1μF 到 GND，确保电源完整性。
3. **ESD 防护**：CLRD125 的 HBM ESD 等级为 ±2kV，低于 LT1258 的 ±4kV。如果设备需要在高静电环境中使用，建议评估增加外部 TVS 二极管。
4. **热设计**：CLRD125 功耗与 LT1258 相近，当前散热设计应可沿用。

### 8.2 软件方面

1. **寄存器地址计算**：CLRD125 的 I2C 地址 = `0x80 + 寄存器号`，不要再使用 LT1258 的 Bank 切换逻辑。
2. **参数范围差异**：CLRD125 的 EQ 是 64 级（0~63），而 LT1258 是较粗的档位。不要将 LT1258 的 EQ 值直接映射到 CLRD125，需要重新标定。
3. **上电时序**：CLRD125 上电后有校准过程，建议软件在初始化前等待或检测 ALL_DONE（Pin 27）状态。
4. **调试文档**：参考 `关于125C寄存器调试建议.pdf` 中的调试经验，可以显著缩短调试周期。

### 8.3 文档与追溯

1. 建议保存 LT1258 和 CLRD125 的两份数据手册，便于后续对比查阅。
2. 调试过程中记录每片芯片的最优参数，形成配置数据库。
3. 如果后续更换芯片批次，建议重新验证信号完整性。

| 高速信号引脚 | ⭐⭐⭐⭐⭐ | 实际使用的 8 对引脚位置完全一致 |
| 未使用引脚 | ⭐⭐⭐⭐⭐ | LT1258 未使用的引脚，CLRD125 恰好也是 NC |
| 控制引脚 | ⭐⭐⭐⭐⭐ | ENSMB/SEL0/SEL1/RESET/VDD_SEL 等完全兼容 |
| I2C 地址 | ⭐⭐⭐⭐⭐ | 0xB0~0xBE 映射完全相同 |
| **硬件改动量** | ⭐⭐⭐⭐⭐ | **FAE 确认 I2C 模式下无需硬件改动** |
| **软件工作量** | ⭐⭐⭐⭐ | I2C 协议和寄存器初始化需重写，但逻辑清晰 |

### 9.2 最终结论

> **CLRD125C-K 替代 LT1258 在硬件上完全可行，且改动量极小（根据 FAE 反馈，I2C 模式下可做到零硬件改动）。主要工作量在于 MCU 固件中 I2C 驱动和寄存器初始化序列的重写。**

**推荐实施步骤**：

1. **验证阶段**：选取 1~2 块样板，只修改软件驱动，验证功能和信号质量
2. **参数标定**：在不同链路条件下标定最优 EQ/DEM/VOD 参数
3. **批量替换**：确认无误后，在后续批次中全面替换，BOM 同步更新
4. **文档归档**：将本报告、调试记录、最优参数表归档，便于后续维护
