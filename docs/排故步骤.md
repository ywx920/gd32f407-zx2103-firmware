这份日志说明：CLRD125在GPIO_I2C1上没有产生任何地址ACK。问题发生在读取ID之前，所以与V0.1/V1.0寄存器差异、配置参数都无关。

关键点：CB2991正常不能证明CLRD125总线正常。

- CB2991：`GPIO_I2C0`，PB6/PB7
- CLRD125/LT1258：`GPIO_I2C1`，PB10/PB11

因此它们是两条独立总线。

## 最可能原因

按优先级排列：

1. CLRD125 Pin51没有供电

LT1258的Pin51是NC，而CLRD125的Pin51是VDD。即使旧板改造后LT1258能够I²C工作，换成CLRD125后也必须保证Pin51接入正确VDD并去耦。

这是替换后出现“全地址NACK”最值得优先检查的差异。

1. ENSMB电平不正确

SMBus从机模式要求：

```
ENSMB约等于VDD
```

如果仍为低电平，Pin49/50会变成DEM配置输入，不会响应任何地址。

不能只根据“这块板以前支持LT1258 SMBus”推断CLRD125当前ENSMB一定正确，应直接测量Pin48。

1. SCL/SDA没有真正连到CLRD125

需要断电测量：

```
PB10 → CLRD125 Pin50
PB11 → CLRD125 Pin49
```

应接近0Ω或串联电阻阻值。

旧板可能通过飞线或补焊连接LT1258，替换芯片、返修或清洗后连接可能发生变化。

1. RESET处于低功耗状态

CLRD125手册定义：

```
RESET=0：正常运行
RESET=1：低功耗
```

请测Pin52，正常应接近0V。

1. 供电模式不完整

检查：

- Pin9、14、36、41、51：VDD
- Pin24：VIN
- Pin25：VDD_SEL
- 裸露焊盘：GND

如果是3.3V模式：

- VIN应为3.3V；
- VDD_SEL应按手册接地；
- 所有VDD脚都必须有电源。

## 当前日志可以排除什么

可以暂时排除：

- 总线被永久拉低：PB10/PB11空闲均为高；
- 单纯地址写错：已经覆盖LT1258旧地址和CLRD125标准地址；
- ID寄存器错误：连地址阶段都没有ACK；
- 寄存器基址`0x00/0x80`错误：Probe不发送寄存器地址。

## 建议立即测量

上电状态下测CLRD125：

| 测量点        | 预期                |
| ------------- | ------------------- |
| Pin48 ENSMB   | 接近VDD             |
| Pin52 RESET   | 接近0V              |
| Pin51 VDD     | 正确电源电压        |
| Pin24 VIN     | 与供电模式一致      |
| Pin25 VDD_SEL | 与2.5V/3.3V模式一致 |
| Pin49 SDA     | 空闲高，有扫描脉冲  |
| Pin50 SCL     | 空闲高，有扫描时钟  |

再用示波器或逻辑分析仪看Pin49/50：

- PB10有时钟、Pin50没有：连接断开；
- Pin50有时钟、Pin49始终高：芯片未进入从机模式、未供电或处于低功耗；
- Pin49在第9个时钟被拉低：实际上有ACK，软件采样时序才需要检查。

目前不建议继续修改地址或ID代码。优先测量Pin51、ENSMB、RESET和PB10/PB11到芯片的导通，这四项中大概率能找到原因。
