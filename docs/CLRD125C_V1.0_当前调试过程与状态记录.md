# CLRD125C V1.0 当前调试过程与状态记录

## 1. 文档目的

本文记录ZX2103/ZX2205-3板卡由LT1258替换为CLRD125C V1.0后的软件适配、通信测试、当前结论和下一步排查方法。

记录时间：2026年6月23日。

## 2. 当前已确认信息

### 2.1 芯片版本

当前实物芯片已经确认是：

```text
CLRD125C V1.0
```

因此后续不再使用旧版V0.1的以下判断：

```text
reg0x44 = 0x55
```

V1.0使用自己的寄存器表和地址规则。

### 2.2 板卡状态

当前实物板卡经过改板，与`zxgd-1_v1.1_20240611.pdf`中的默认焊接状态不完全一致。

已知情况：

- 板卡已经支持SMBus模式；
- 改板前LT1258可以通过MCU I2C正常配置；
- CLRD125C的Pin51供电已经确认正常；
- ENSMB电平及SMBus模式选择已经确认正常；
- CLRD125C使用MCU的GPIO模拟I2C1；
- CLRD125C总线引脚为PB10/PB11；
- CB2991使用另一条GPIO模拟I2C0总线PB6/PB7。

因此：

```text
CB2991通信正常不能证明CLRD125C所在的PB10/PB11总线正常。
```

## 3. LT1258原配置情况

原LT1258工程通过GPIO模拟I2C进行寄存器读写。

原地址定义：

| 器件 | 7位地址 | 线上写地址 |
|---|---:|---:|
| LT1258-1 | 0x18 | 0x30 |
| LT1258-2 | 0x1C | 0x38 |
| LT1258-3 | 0x20 | 0x40 |
| LT1258-4 | 0x24 | 0x48 |

原LT1258主要配置效果：

```text
SRXB0/SRXB1/DRXA0/DRXA1 EQ约17.6 dB
DTXB0/DTXB1/STXA0/STXA1 VOD约0.8 Vp-p
DEM约-4.4 dB
Fanout关闭
```

对应CLRD125C目标路径：

```text
S_INB0 -> D_OUT0
S_INB1 -> D_OUT1
D_IN0  -> S_OUTA0
D_IN1  -> S_OUTA1
```

CLRD125C初始目标参数：

```text
CTLE code = 0x09，EN_HF=1，约17.7 dB
非线性模式
VOD code = 010，约0.8 Vp-p
DEM code = 010，约-5 dB
Fanout关闭
```

CLRD125C没有与LT1258完全相同的-4.4 dB挡位，因此暂时选择最接近的-5 dB，后续需要与-3.5 dB进行眼图和BER对比。

## 4. CLRD125C V1.0通信规则

V1.0资料给出的标准地址范围：

```text
7位地址：0x58～0x67
AD[3:0]=0000时：0x58
线上写地址：0xB0
线上读地址：0xB1
```

当前底层`gpioI2cRead/gpioI2cWrite`接口接收7位地址，函数内部自动左移一位。

CLRD125C不使用LT1258的Bank切换方式，所以不能继续执行：

```c
Write(0xFF, 0x80);
Write(0xFF, 0x81);
```

## 5. 已进行的软件测试

### 5.1 project_up_new测试

主工程实现了：

1. 检查PB10/PB11总线空闲状态；
2. 地址探测；
3. 扫描CLRD125C V1.0地址`0x58～0x67`；
4. 找到ACK后读取寄存器；
5. 按LT1258等效目标配置CLRD125C；
6. 对配置寄存器执行回读校验；
7. 读取RX_DETECT和RX_LOS。

实际结果：

```text
SCL=1，SDA=1
0x58～0x67全部NACK
```

此前也测试过以下兼容地址：

```text
0x18、0x1C、0x20、0x24、0x30
```

同样全部NACK。

失败位置是在从机地址ACK阶段，尚未进入寄存器读写和配置阶段。

### 5.2 project_up_old对照测试

为了排除新工程I2C扫描、重试和配置框架引入的问题，将`project_up_old`改造成CLRD125C V1.0对照测试工程。

保留内容：

- 原PB10/PB11 GPIO模拟I2C底层；
- 原`lt1258Init()`调用入口；
- 原Keil工程组织形式；
- 原I2C位操作时序。

替换内容：

- 删除LT1258 Bank配置；
- 地址改为扫描`0x58～0x67`；
- 寄存器改为CLRD125C V1.0寄存器；
- 增加只发送从机地址的`gpioI2cProbe()`；
- 增加逐项读、写、回读打印；
- 关闭RA、GA、LOS、温度和电压的循环打印。

实际打印：

```text
[CLRD125-OLD] probe 7-bit=0x58 write=0xB0 ... NACK
...
[CLRD125-OLD] probe 7-bit=0x67 write=0xCE ... NACK
[CLRD125-OLD] no CLRD125C V1.0 address ACK
```

结论：

```text
project_up_new和project_up_old均在地址阶段全部NACK。
```

## 6. 当前已经基本排除的因素

由于两个工程使用不同的上层初始化代码，但均在地址ACK阶段失败，目前可以基本排除：

1. `project_up_new`新增的地址扫描逻辑；
2. 新工程的重试逻辑；
3. V0.1/V1.0软件识别逻辑；
4. CLRD125配置表中的CTLE、VOD、DEM数值；
5. CLRD125路由配置值；
6. 寄存器地址是直接偏移还是增加0x80；
7. 芯片ID寄存器读取方式；
8. LT1258 Bank机制与CLRD125扁平寄存器机制的差异。

原因是以上内容都发生在从机地址ACK之后，而当前芯片没有在地址阶段应答。

## 7. 当前尚不能排除的问题

### 7.1 PB10/PB11到芯片管脚的实际连接

断电测量：

```text
PB10/SCL -> CLRD125C Pin50/SCL
PB11/SDA -> CLRD125C Pin49/SDA
```

必须直接测到芯片焊盘，不能只测中间测试点。

### 7.2 RESET状态

CLRD125C定义：

```text
RESET=0：正常运行
RESET=1：低功耗
```

需要上电测量Pin52，正常应接近0 V。

### 7.3 SCL/SDA是否接反

正确连接：

```text
PB10 -> Pin50/SCL
PB11 -> Pin49/SDA
```

### 7.4 上拉阻值过小

资料中曾提到四颗1 kΩ上拉并联，等效约：

```text
Rpull-up = 250 Ω
```

3.3 V下从机产生ACK低电平需要的灌电流约为：

```text
3.3 V / 250 Ω = 13.2 mA
```

如果当前总线确实为250 Ω上拉，CLRD125C可能无法把SDA可靠拉低。

建议断电测量SCL、SDA到VDD的等效阻值。必要时临时改为：

```text
1 kΩ单颗
或2.2 kΩ～4.7 kΩ
```

再测试地址ACK。

### 7.5 ACK实际存在但软件没有采到

软件打印NACK不等于芯片管脚上一定没有ACK，需要示波器或逻辑分析仪确认第9个时钟。

### 7.6 其他供电和焊接问题

虽然Pin51和ENSMB已经确认正常，仍需视情况检查：

- Pin9、14、36、41、51的VDD；
- Pin24 VIN；
- Pin25 VDD_SEL；
- 裸露焊盘GND；
- 芯片焊接、虚焊、桥连；
- CLRD125C上电稳定时间。

## 8. 下一步推荐测试

### 8.1 第一优先级：抓取0xB0地址波形

使用示波器或逻辑分析仪直接连接：

```text
CLRD125C Pin50/SCL
CLRD125C Pin49/SDA
```

观察发送`0xB0`时：

1. START是否正常；
2. 地址字节是否确实为`0xB0`；
3. SCL是否有8个地址时钟加1个ACK时钟；
4. 第9个时钟期间SDA是否被芯片拉低。

判断：

| 实测现象 | 可能结论 |
|---|---|
| PB10有时钟，Pin50无时钟 | SCL连接断开 |
| PB11有数据，Pin49无数据 | SDA连接断开 |
| Pin49/50均有完整波形，第9位保持高 | 芯片没有应答 |
| 第9位SDA已经拉低，软件仍打印NACK | MCU采样时序或电平门限问题 |
| SDA只能下降到较高电压 | 上拉过强或芯片下拉能力不足 |

### 8.2 第二优先级：测量关键静态电平

| 管脚 | 项目 | 预期 |
|---|---|---|
| Pin48 | ENSMB | 已确认接近VDD |
| Pin52 | RESET | 接近0 V |
| Pin51 | VDD | 已确认正常 |
| Pin24 | VIN | 符合当前供电模式 |
| Pin25 | VDD_SEL | 符合当前2.5 V/3.3 V模式 |
| Pin49 | SDA空闲 | 高电平 |
| Pin50 | SCL空闲 | 高电平 |

### 8.3 第三优先级：测量总线上拉

断电后分别测量：

```text
SCL到VDD阻值
SDA到VDD阻值
```

若接近250 Ω，应优先减弱上拉后复测。

### 8.4 第四优先级：调整GPIO电气模式

当前旧GPIO模拟I2C中：

```text
SDA使用开漏
SCL使用推挽
```

标准SMBus更适合SCL/SDA均采用开漏输出。若确认硬件连接和ACK下拉能力正常，但通信仍不稳定，再考虑将SCL改为开漏并调整时钟速度。

## 9. 当前阶段结论

当前最可靠的结论是：

```text
CLRD125C V1.0在PB10/PB11总线上没有被软件检测到地址ACK。
```

旧工程和新工程得到相同结果，因此继续修改CTLE、VOD、DEM、路由或寄存器表不会解决当前问题。

现阶段应将重点从配置软件转移到：

1. 芯片Pin49/50处的实际波形；
2. PB10/PB11到芯片的导通；
3. RESET电平；
4. SDA/SCL上拉阻值；
5. 第9个时钟的ACK低电平幅度。

只有地址ACK成功后，才能继续判断寄存器地址格式和CLRD125C信号调理参数是否正确。
