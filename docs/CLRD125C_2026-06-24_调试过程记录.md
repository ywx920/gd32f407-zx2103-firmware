## 2. 资料依据

### 2.1 CLRD125C V1.0 手册

参考资料：

`CLRD125/数据手册/CLRD125C-K_V1.0.pdf`

关键结论：

1. CLRD125C 通过 `ENSMB` 选择模式：
   - `ENSMB = 0`：引脚模式。
   - `ENSMB = 1`：SMBus 从模式，MCU 可访问配置寄存器。
   - `ENSMB = Floating`：SMBus 主模式，从外部 EEPROM 加载配置。
2. CLRD125C 的 SMBus 从地址由 `AD[3:0]` 决定。
3. 手册第 20 页 `8.2 系统总线管理（SMBus）和寄存器配置` 给出的地址表为：

| AD[3:0] | 地址字节 |
|---|---:|
| 0000 | `0xB0` |
| 0001 | `0xB2` |
| 0010 | `0xB4` |
| 0011 | `0xB6` |
| 0100 | `0xB8` |
| 0101 | `0xBA` |
| 0110 | `0xBC` |
| 0111 | `0xBE` |
| 1000 | `0xC0` |
| 1001 | `0xC2` |
| 1010 | `0xC4` |
| 1011 | `0xC6` |
| 1100 | `0xC8` |
| 1101 | `0xCA` |
| 1110 | `0xCC` |
| 1111 | `0xCE` |

注意：表中的 `0xB0~0xCE` 是 8-bit 线上的写地址。当前工程 `gpioI2cWrite()` / `gpioI2cRead()` 接收 7-bit 地址，因此代码中使用：

```text
0xB0 >> 1 = 0x58
0xCE >> 1 = 0x67
```

所以 CLRD125C V1.0 的理论扫描范围为：

```text
7-bit 地址：0x58 ~ 0x67
8-bit 写地址：0xB0 ~ 0xCE
```

### 2.2 LT1258 手册

参考资料：

`LT1258_U2_Datasheet_R1.1.pdf`

关键结论：

LT1258 手册第 12 页 `7.3 Device Configuration Address` 也使用 `AD[3:0]` 设置地址，但它同时列出了两组地址：

| AD[3:0] | LT1258 I2C Device Address | LT1258 I2C/SMBus Device Address |
|---|---:|---:|
| 0000 | `0xB0` | `0x30` |
| 0001 | `0xB2` | `0x32` |
| 0010 | `0xB4` | `0x34` |
| 0011 | `0xB6` | `0x36` |
| 0100 | `0xB8` | `0x38` |
| 0101 | `0xBA` | `0x3A` |
| 0110 | `0xBC` | `0x3C` |
| 0111 | `0xBE` | `0x3E` |
| 1000 | `0xC0` | `0x40` |
| 1100 | `0xC8` | `0x48` |

原理图中出现：

```text
I2C Device Address        --- B8
I2C/SMBus Device Address  --- 38
```

这与 LT1258 手册中 `AD[3:0] = 0100` 对应关系一致。

对 CLRD125C 的参考意义：

1. 说明原板卡 LT1258 地址由 `AD[3:0]` 设定。
2. 如果 CLRD125C 与 LT1258 的 AD 引脚兼容，并且板卡地址电阻未改，则相同位置上的 CLRD125C 可能继承相同的 `AD[3:0]` 电平。
3. 但 CLRD125C V1.0 手册没有列出 LT1258 的 `0x30~0x4E` 兼容地址列，因此不能直接认定 CLRD125C 会响应 LT1258 旧地址。

例如原 LT1258 某位置为：

```text
I2C Device Address        = 0xB8
I2C/SMBus Device Address  = 0x38
```

若按 CLRD125C V1.0 地址表，则该位置的 CLRD125C 应优先测试：

```text
7-bit 地址：0x5C
8-bit 写地址：0xB8
```

同时为了兼容性排查，也测试 LT1258 旧地址：

```text
7-bit 地址：0x1C
8-bit 写地址：0x38
```

### 3.4 增加全 7-bit 地址扫描范围

文件：

`20241202/project_up_new/bsp/clrd125c_v1.h`

```c
#define CLRD125C_DEVICE_ADDR_FULL_MIN     0x00U
#define CLRD125C_DEVICE_ADDR_FULL_MAX     0x7FU
```

说明：

当前为 7-bit 地址全覆盖扫描。注意 `0x00` 包含 General Call，`0x78~0x7F` 属于特殊/保留地址。当前扫描只发送地址并检查 ACK，不写寄存器，用于排查未知地址。

### 3.5 增加 I2C0/I2C1 双总线扫描

文件：

`20241202/project_up_new/bsp/clrd125c_v1.c`

新增扫描流程：

1. 扫描 I2C0。
2. 扫描 I2C1。
3. 每条总线均执行：
   - CLRD125C V1.0 范围：`0x58~0x67`。
   - LT1258 旧地址范围：`0x18~0x27`。
   - 全 7-bit 地址范围：`0x00~0x7F`。
   - 全 8-bit 写地址范围：`0x00~0xFE`，只扫描偶数写地址字节。
4. 前两段打印 ACK/NACK。
5. 全地址扫描只打印 ACK，避免日志过长。

说明：

I2C/SMBus 标准地址传输实际为：

```text
7-bit 从机地址 + 1-bit 读写位
```

因此所谓 8-bit 写地址，本质上等于：

```text
8-bit 写地址 = 7-bit 地址 << 1
```

全 7-bit 地址扫描 `0x00~0x7F` 已经覆盖所有偶数 8-bit 写地址 `0x00~0xFE`。新增 8-bit 写地址扫描主要用于现场按手册标注的 `0xB0/0xB8/0x30/0x38` 等线地址直接观察结果，避免 7-bit/8-bit 概念混淆。

### 3.6 修正 CLRD125C OK 判定

之前扫描到任意 I2C 设备就会返回 `STA_OK`，导致扫到 CB2991 也会显示：

```text
CLRD125C=OK(SMBUS)
```

这不准确。

已修改为：

```text
只有 CLRD125C V1.0 范围或 LT1258 旧地址范围内扫到 ACK，才认为 CLRD125C 被找到。
```

全地址扫描扫到其他器件，只用于证明总线可用，不再作为 CLRD125C OK 的依据。

## 5. 关于 I2C 频率的确认

当前工程使用的是 GPIO 模拟 I2C，不是 MCU 硬件 I2C 外设。

文件：

`20241202/project_up_new/bsp/gpio_i2c.c`

当前延时参数：

```c
#define I2C_DELAY_TIME (20*10)
```

即：

```text
I2C_DELAY_TIME = 200
```

发送 1 bit 的主要时序约为：

```text
delay(I2C_DELAY_TIME / 4)
delay(I2C_DELAY_TIME / 4)
delay(I2C_DELAY_TIME / 2)
```

因此 1 bit 约消耗：

```text
I2C_DELAY_TIME = 200 个 delay 单位
```

而 `delay()` 内部还有：

```c
for(i = 0; i < cnt; i++)
{
    for(j = 0; j < 40; j++);
}
```

结论：

```text
当前 I2C0/I2C1 不是 400 kHz。
两条总线共用同一套 GPIO 模拟 I2C 代码，因此频率相同。
实际频率大概率为几 kHz 到几十 kHz 级别，需用示波器测 SCL 才能精确确认。
```

CLRD125C 手册中的 400 kHz 是 SMBus 从模式最高支持速率，不代表必须以 400 kHz 通信。当前速率偏慢通常不会导致地址 NACK。

## 6. 当前问题判断

当前没有扫到 CLRD125C 地址，不应继续写寄存器配置。

优先怀疑方向：

1. CLRD125C 没有真正进入 SMBus 从模式。
   - 重点检查 `ENSMB` 是否为高。
2. CLRD125C 处于 RESET/低功耗状态。
   - 重点检查 `RESET` 是否为低。手册说明 `RESET=0` 为正常工作，`RESET=1` 为低功耗模式。
3. CLRD125C 的 SCL/SDA 未连接到当前 MCU 扫描的 I2C0 或 I2C1。
4. CLRD125C 供电异常或焊接异常。
5. CLRD125C 的 AD[3:0] 电平与预期不一致，但由于已经做过全地址扫描，这个可能性低于前几项。

## 7. 建议下一步硬件验证

建议用示波器或逻辑分析仪直接测 CLRD125C 芯片引脚：

| 信号 | CLRD125C 引脚 | 期望状态 |
|---|---:|---|
| SCL | 50 | 扫描时应有时钟波形 |
| SDA | 49 | 扫描时应有数据波形，ACK 位可能被芯片拉低 |
| ENSMB | 48 | SMBus 从模式应为高 |
| RESET | 52 | 正常工作应为低 |
| AD0 | 54 | 地址选择脚 |
| AD1 | 53 | 地址选择脚 |
| AD2 | 47 | 地址选择脚 |
| AD3 | 46 | 地址选择脚 |

验证顺序：

1. 测 CLRD125C `ENSMB` 是否为高。
2. 测 CLRD125C `RESET` 是否为低。
3. 烧录当前扫描程序，测 CLRD125C pin 50/pin 49 是否有 I2C 波形。
4. 如果 MCU 端有波形但 CLRD125C 引脚无波形，说明总线路径/连接不对。
5. 如果 CLRD125C 引脚有波形但无 ACK，说明芯片未进入 SMBus 从模式、复位/供电异常、或地址/器件状态异常。
